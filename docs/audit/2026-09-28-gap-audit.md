# llm-polarization: what is missing to deliver the study

Audited: commit `c697495` (2026-09-16, then HEAD of `claude/wizardly-goodall-2xnphr` and identical to
`main`). Audit date 2026-09-28, which is W6. **All line numbers refer to `c697495`.** During the audit a
docs pass landed as `f63a6a2` ("docs: bring READMEs, design records and code comments in line with the
code"). Its changes to `harness/*.py` are comments and docstrings only, so every code finding still
holds, but code line numbers have shifted by a few lines. Doc inconsistencies that `f63a6a2` fixes are
marked **(f63)**.

Verification: `pytest harness/tests` gives 204 passed and 2 skipped (live). I ran three probes in the
scratchpad, not in the repo: `probe_rand.py`, `probe_resume.py` and `probe_descope.py`. They back F6, F8
and F9.

## Findings

**F1. Blocker: no persona catalogue.** `prompts/personas/catalogue.json` does not exist. Only
`catalogue.example.json` exists: all placeholder text, one variant per level. The grid needs 15
backstories, 10 anchor sets and 30 persona texts (`docs/decisions/factorial.md:136-141`). Moderate anchors
also have to be scoreable centrist positions (`factorial.md:105-111`). The randomizer, the pilot, the
seeker choice and every wave are downstream of this file.

**F2. Blocker: the survey instrument does not measure the treatment topics.**
- `instruments/batteries.json:2-3` is `0.1.0-placeholder` with `adapted: false`, and the US adaptation
  (a W2 task) is not done.
- No item touches decarbonization or climate (grep for climate/carbon/energy/emission returns nothing). The
  only immigration item is the generic "made more restrictive"; none is about militarization of
  enforcement. Half the design (the decarbonization topic) has no topic-specific outcome item.
- Items point in different directions (immigration: high = right; the other four: high = left). There is
  no `direction` field and no index definition, so "polarization" is not yet operationalized as a number.

**F3. Blocker: no analysis pipeline.** `analysis/README.md:4` says "Nothing here yet." Nothing in the repo
does any of the following:
- selects the latest complete attempt (the rule exists only inside the harness, `scorer.py:199-201`);
- applies the pre-registered technical exclusions (error rows, `truncated`, judge failures;
  `persona-stability.md:154-161`);
- pairs pre and post rows per item, reverse-codes, builds indices, or estimates the ITT/ATE against
  control with `role` as a random effect;
- runs the shape test (`factorial.md:112-119`) or the dose-response on adherence;
- produces the appendix rates the checklist requires (cache_warning, truncated, `attempt>1` by condition,
  null/salvaged answers, `finish_reason=length`, refusal rate; `REPRODUCIBILITY.md:303-313`).

**F4. Blocker: no pre-analysis plan and no power analysis.** No PAP file exists, and grep finds no
power/MDE computation. N=135 per cell was derived from compute (`factorial.md:22-32`). The first descope
step is "135 to 90 … loses power" (`factorial.md:154`), but how much power is never quantified. The
runway put pre-registration in W5 (Sep 21-27, `research-design.md:113`), which has passed. Several
decisions are explicitly deferred to the PAP (`factorial.md:186-187`, `persona-stability.md:141-147,
171-172`, `REPRODUCIBILITY.md:232`).

**F5. Blocker: the pilot has left no trace, and the schedule inputs are unresolved.**
- `data/` holds only `README.md` and `.gitkeep`, and no run manifest is committed. README still says "No
  pilot data yet" (`README.md:56`).
- The seeker model is "filled in after the Sep 18 pilot" (`factorial.md:57`) and is still unnamed.
- The judge is named nowhere. `config.example.json:11` points it at `:8099`, which is the resident
  `llm-deep` qwen3.8 tier (`models/serving/README.md:35`).
- The wave budget is "about 20.5 to about 40 days depending on seeker speed" against 21 allocated
  (`factorial.md:34-47`). Waves W7-W9 start 2026-10-05.

**F6. Important: the documented pilot command fails with a real catalogue.** `randomize.py:152-154`
refuses an `n_per_cell` that does not divide by the number of variants. `--n-per-cell 5`
(`harness/README.md:19`, `prompts/README.md:42`, `randomize.py:6`; pilot design `factorial.md:145`) fails
when a level has 3 variants. Verified: "n_per_cell 5 does not split evenly across the 3 role variant(s)".
`test_randomize.py:104` only exercises the 1-variant example catalogue. Pick 3 or 6 per cell, or pilot
one variant per level, and record the choice.

**F7. Important: judge compute is unbudgeted and serial.**
- `cmd_score` builds one judge handle on slot 0 (`run.py:524`), and `Scorer.score_run` loops without
  concurrency (`scorer.py:256-295`).
- `main` scope is 10 seeker turns × 2 metrics = 20 calls per dyad, or about 178,200 calls for 8,910
  dialogues. `stance` scope and the second judge come on top.
- `line_to_line` prompts carry every earlier line (up to ~12k tokens) and get no prefix reuse between
  targets. At 5-10 s per call that is roughly 10-20 days of serial judge time. This is an estimate that
  the pilot should measure.
- None of this is in `compute-budget.md` or `RUN_APPROACH.md`. `persona-stability.md` (design) §4 only
  says "run the judge … after each wave."

**F8. Important: resume can mix instruments, manifests and code without a trace.**
- `write_manifest` compares only `RUN_AFFECTING_CONFIG` (`log.py:93, 105-109`), and `batteries` there is a
  path string.
- `_verify_identity` checks only model and template sha (`run.py:356-366`).
- The manifest is never rewritten, yet `ctx` uses the new file's sha and items (`run.py:425-427`).

`probe_resume.py` shows the result. After an in-place edit of `batteries.json` and a resume with a
different `--manifest`, both runs exit 0. `manifest.json` keeps the old batteries sha and
`input_manifest` (`m1.jsonl`), while dyad d1's survey rows carry a new sha. Likewise:
- A resume from a new commit is undetectable: `harness_commit` is recorded once, and `turns`/`surveys`
  rows carry no commit (`dialogue.py:115-118`, `survey.py:87-92`).
- A llama.cpp upgrade that keeps the template passes: `build_info` is not re-checked.

This contradicts `REPRODUCIBILITY.md:44-46` and standards rows 8, 10 and 12. The **(f63)** README now
discloses the path-only comparison but does not fix it.

**F9. Important: descoping and cross-arm consistency are unguarded.**
- Re-running the randomizer with `--n-per-cell 90` and the same seed and prefix produces dyad_ids that are
  a subset of the 135 manifest. Their seeds differ (only 30/1980 match, `probe_descope.py`), so a
  "descoped" arm would not be paired with an arm already run at 135. Nothing documents that the cut must
  subset the existing manifest.
- Nothing requires the three arms to share `run_seed`, `now`, the input manifest or the judge
  (`REPRODUCIBILITY.md:285-286` "check it by hand").
- The judge-family check is per run (`scorer.py:232-239`). A judge that is refused for the qwen arm (for
  example the qwen3.8 default) is accepted for the others, which invites a judge-by-arm confound. A
  study-level lock file checked by `run` and `score` would close this.

**F10. Important: the control and the stance metric are mis-specified in the code.**
- `select_targets` never looks at `condition` (`scorer.py:86-117`), so `main` scope scores and `flags`
  flags control dyads. `factorial.md:95` says adherence scoring does not apply to them. `flags` then
  reports an `ideology none` rate.
- `alignment` asks how far the mentor agrees "with the position the PERSONA holds" (`scorer.py:49-50`).
  That is undefined for the bare control, which has no position, so the turn-level DV has no zero point.
- The metric is persona-relative. The dose-response and shape test over five ideology levels need a
  signed left-right transform, and none is specified.
- The judge also sees the full persona, so it is not blind to condition.

**F11. Important: the pre-measure is a constant, and the baseline is undefined.** Pre-survey prompts are
`[user: item]` with no context (`survey.py:77-83`) at temperature 0 (`survey.py:16`). Every dyad in an arm
therefore gets the same greedy answer, up to batching noise, so pre/post reduces to post-only between
cells. The "1,000-administration baseline" (`research-design.md:73, 113`) has no definition and no code
path, since `run` always runs a dialogue. At T=0 it would be 1,000 copies.

Post items are appended as a user turn after the dialogue (`survey.py:83`). They therefore measure in-context
accommodation to the interlocutor. That is the sycophancy confound the design names, and the PAP must say
the bare control is the only thing that separates it.

**F12. Important: calibration and pilot protocols are promised but have no tooling.** Nothing exists for:
- sampling 100-150 pilot turns stratified by turn and ideology, a label file format, Krippendorff's
  alpha/kappa, or threshold selection (`persona-stability.md:102-105`). `flags` hard-requires the
  threshold (`run.py:720`).
- Q&A probes (§3).
- the "unconstrained run on a sample" check for reasoning models under the grammar (spec `:139`). The
  survey always sends `json_schema` (`survey.py:96`).
- refusal-rate detection (`persona-stability.md:159-161`).

**F13. Important: reasoning output and the real templates are untested.** Dialogue text goes into the
transcript and back into the partner's prompt raw (`dialogue.py:131-146`). Only the survey parser strips
`<think>` (`parser.py:23-24`). Nothing handles gpt-oss harmony channel output (analysis versus final).

Template tests use toy mimics (`tests/conftest.py:11, 20`), not the arm GGUF templates. The live test ran
Qwen3-4B with seeker and mentor on one server (`test_live.py:21`), a setup `run` itself refuses. No
committed manifest shows `check` (parity, cache probe) passing on qwen3.6, gpt-oss or Olmo. The Olmo gate
(`harness/README.md`, Servers) is unrecorded.

**F14. Important: the archive record never reaches git.**
- `.gitignore:13-15` un-ignores only `manifest.json` and `judge-*.json`. The procedure's `SHA256SUMS` and
  `archive.json` (`REPRODUCIBILITY.md:97-110`) stay ignored, so a clone cannot locate the tier-3 data.
- The input dyad manifest and its `-assignment.json` (the randomization record, `randomize.py:198-214`) are
  written wherever `--out` points (the docs use the repo root). They are neither ignored nor covered by the
  archival rule.
- `write_judge_manifest` overwrites `judge-<sha>-<scope>.json` on a third differing pass
  (`run.py:613-620`). **(f63)** `data/README.md` now documents this but does not fix it.

**F15. Important: the budget inputs are optimistic.**
- Every days-per-arm figure assumes 200 tokens per message (`compute-budget.md:26`,
  `RUN_APPROACH.md:87`), but `n_predict` is 300 (`config.example.json:8`). Verbose advisors cost up to
  1.5x.
- `bench_parallel.py` measured one server at a time. Seeker and mentor on one GPU at np=8 each have never
  been measured together, and neither has their memory (Olmo np=8 alone reached 80 GiB with the tiers up).
- `RUN_APPROACH.md:82` recommends np=4 for Olmo while every other doc says 8.

**F16. Important: some errors escape as tracebacks.**
- `main` catches only `ServerError`, `ManifestMismatch` and `ValueError` (`run.py:740`).
- `cmd_check` catches only `ServerError` around `build_agent` (`run.py:336-341`). So a wrong
  `gguf_py_path` or a missing GGUF (`TemplateError`, `templates.py:12, 85`) or an `os.stat` failure
  (`run.py:62`) tracebacks out of `check`, `run` and `score`.
- `cmd_survey` can `KeyError` (`run.py:504`).
- `survey` and `score` return 0 even when items or judge calls errored (`run.py:511-514, 538-539`).

**F17. Important: test gaps.** The harness has 204 tests, but these behaviours are untested:
- resume with a changed instrument, input manifest or commit (F8);
- resume of a `started` (crashed) dyad (only `failed` is covered, `test_run.py:120`);
- Ctrl-C through the real main-thread path. The test raises `KeyboardInterrupt` inside the worker at
  concurrency 1 (`test_run.py:363-369`), so "in-flight dyads finish" is never asserted;
- `survey` run twice (no idempotence; `run.py:503-512` appends duplicate `readministered` rows);
- whether a rebuilt post-survey prompt hashes the same as the in-run one;
- `flags --judge` prefix resolution and its ambiguity error (`run.py:549-553`);
- the `agreement` path with fewer than two judges;
- the pilot randomizer with 3 variants (F6);
- the error paths in F16;
- real templates (F13).

`models/benchmarks` and `models/serving` have no tests (acceptable).

**F18. Nice-to-have: engineering hygiene.**
- No CI, `pyproject.toml`, lint config or `.python-version`. The code needs Python 3.9 or later
  (`cancel_futures`, `run.py:467`).
- `requirements.lock` lacks pytest and gguf-py's own dependencies (tqdm and PyYAML per upstream gguf-py;
  verify against the pinned checkout) and has no hashes.
- `data_dir` and `batteries` defaults resolve against the working directory, while `grid` is absolute
  (`run.py:24, 27`). `randomize --grid` is also relative (`randomize.py:220`).
- `/home/alex` is hard-coded in `config.example.json:3`, `harness/README.md` and every
  benchmark/serving script.
- The serving wrappers bind `0.0.0.0`.
- No versioned launch script exists for the study's seeker, mentor and judge servers
  (`models/serving/README.md:44-45`).
- No secrets were found; `.env` is ignored.

**F19. Nice-to-have: smaller recording gaps.**
- `manifest.environment` omits numpy and gguf-py dependency versions (`run.py:659-667`).
- Survey and judge requests send `top_p` 0.95 but do not record it (harmless at T=0).
- `CITATION.cff` has no ORCID (`REPRODUCIBILITY.md:269`).
- The §4a reproduce-one-dialogue check exists only as a doc snippet, not as code with a test.
- The server command line is still open (row 9).

## What I would do first

1. **Unblock the pilot.** Write `catalogue.json`. Adapt the batteries, adding at least one
   topic-specific item for each topic with direction coding. Run the pilot with an `n_per_cell` that
   divides by 3 (F1, F2, F6).
2. **Run `check` on the box against all three mentor arms, the seeker candidates and a judge.** Choose one
   judge from a family outside all three arms and fix it study-wide. Commit the pilot manifests. From the
   pilot, recompute the budget including the seeker half, real turn lengths and judge time, and
   parallelize the scorer across judge slots (F5, F7, F13, F15).
3. **Write and register the PAP.** It should cover the outcome index and scoring, the estimands, a
   power/MDE simulation from pilot post-survey variance, technical exclusions, the signed stance
   transform, control handling, the baseline definition and a subset-not-re-randomize descope rule (F4,
   F9, F10, F11).
4. **Build `analysis/`.** That means a loader with latest-complete and exclusion filters, pre/post item
   and index tables, ATE against control with a `role` random effect and dyad clustering across arms, the
   shape test and the appendix-rate script. Also turn the §4a verifier into code with a test (F3, F19).
5. **Close the provenance holes before wave 1.**
   - On resume, refuse a changed batteries sha, input-manifest sha, `harness_commit` or `build_info`, or
     stamp the commit on every row.
   - Exclude control dyads from adherence scoring.
   - Un-ignore `archive.json` and `SHA256SUMS`, and archive the input manifest and assignment log.
   - Catch `TemplateError` and `OSError` in `main`.
   - Add the F17 tests (F8, F10, F14, F16, F17).
